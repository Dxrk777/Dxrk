## Detalle por área (para las Release notes de GitHub)

### DxrkMemory — recall híbrido local + ciclo de vida (Phases 0–3)

- **Recall híbrido stdlib-only** (`dxrk/memory/vectors.py`, `dxrk/memory/backend/sqlite.py`):
  vectores locales por hashing trick (tokens + char 3-grams con padding,
  `md5` → 512 buckets, `DIM = 512`), coseno ponderado por IDF estilo BM25
  sobre el pool de candidatos, fusión
  `0.6·cos + 0.3·BM25 + 0.05·recency + 0.05·importance + 0.03·access`.
  Harness de eval en `tests/test_memory_recall_eval.py` (queries
  conceptuales sin overlap léxico, `precision@k`/`recall@k`).
- **Write-time dedupe + decay + episodios KG** (`dxrk/memory/palace.py`,
  `dxrk/memory/scoring.py`, `dxrk/memory/graph.py`): colapso de
  near-duplicates en escritura, scoring con half-life 180d (`filed_at`) +
  30d (`accessed_at`), episodios KG por versión de archivo con
  `supersede_source` (re-mine idéntico = no-op, jamás `delete`),
  detección de contradicción con `supersedes`/`superseded_by`.
- **4 herramientas MCP nuevas** (19 → 23 `dxrk_memory_*` en
  `dxrk/memory/mcp_server.py`): `dxrk_memory_consolidate`,
  `dxrk_memory_forget`, `dxrk_memory_pin`, `dxrk_memory_timeline`.
  Budgets por wing (`DEFAULT_MAX_ENTRIES_PER_WING = 1000`,
  `wing_usage()`/`budgets()`, `dxrk_memory_status` incluye `budgets`) y
  timeline cronológico (`session` + `file` + `pin`, ventana
  `[since, before)`).
- **Limpieza:** paquetes muertos `dxrk/memory/cortex/` (15 archivos) y
  `dxrk/memory/autonomous/` (8 archivos) eliminados (−3537 líneas);
  `docs/enterprise.md` y `mkdocs.yml` actualizados.

### Sesiones — durabilidad + backend SQLite opt-in (Phases 0–4)

- **Escrituras atómicas durables** (`dxrk/utils/session_storage.py`):
  tmp + `fsync` + `os.replace` + `fsync` del directorio padre en todos los
  paths; índice con self-heal (`_rebuild_index_from_disk`), fallback `.gz`
  y cuarentena (`.quarantine/` en `dxrk/commands/session.py`).
- **CLI sobre el backend seleccionado por entorno** con migración-on-load
  (`migrate_to_current`) y sanitización de IDs
  (`_validate_session_id`: rechaza path traversal).
- **Backend SQLite-WAL opt-in:** `DXRK_SESSION_BACKEND=sqlite`
  (`open_session_storage()`; `FileStorage` sigue siendo el default),
  misma semántica + suite de conformancia
  (`tests/test_session_phase03_sqlite.py`, 29 tests).
- **Cobertura:** `dxrk/commands/rewind.py` 98%,
  `dxrk/commands/resume.py` 100%, `dxrk/commands/share.py` 100%
  (`tests/test_commands_rewind_resume_share.py`, 33 tests).

### Swarm — dispatch real + linkage con sesiones

- Dispatch real (`dxrk/utils/swarm_schedule.py`: pool genérico de workers,
  selección least-loaded / work-stealing; corregido el
  `"backend worker not found"`), health honesto
  (`dxrk/utils/swarm_supervise.py`: probe pluggable, threshold de fallos →
  `StatusUnhealthy` alcanzable), event bus real
  (`dxrk/utils/swarm_events.py`: `Subscribe`/`Publish`/dispatch),
  coordinador con stats de salud y linkage sesión↔swarm
  (`dxrk/utils/swarm_session.py`: `SwarmTaskStore`,
  `session_id` en tasks/results, `session_summary`).
  Suite: `tests/test_swarm_phase4.py` (19 tests).
